# 오탐율 측정 (ESC-50, dev @ 2519f83 model.tflite)

재현:
```
git clone --depth 1 https://github.com/karolpiczak/ESC-50.git
pip install ai-edge-litert soundfile librosa
python3 extract.py ESC-50 ../../assets/models win.npz     # 창별 RMS·확률 추출 (~1분)
python3 simulate.py ESC-50 win.npz results.json            # 앱 판정 로직 적용
```
- 비위험음: ESC-50 중 car_horn·siren 제외 48개 클래스 1,920클립(5초, 총 2.67시간)
- 판정 로직은 lib/services/sound_detector.dart 그대로: 16kHz·15600창·0.25초 hop, 클래스별 임계값(0.5/0.5/0.5/0.7),
  RMS<0.012 스킵, 연속 확인(2/2/2/3), 알림 후 3초 억제
- 클립 오탐율 = 알림이 1회 이상 뜬 클립 / 전체 비위험 클립

## 결과

비위험 1,920클립 중 알림이 1회 이상 뜬 클립 비율. 탐지율은 ESC-50 car_horn·siren 각 40클립 기준.

### 판정 단계별 (`results.json`, #37 이전 임계값 0.5/0.5/0.5/0.7)

| 설정 | 클립 오탐율 | 시간당 오알림 | 탐지율 horn / siren |
|---|---|---|---|
| 모델 단독 (무음 스킵·연속 확인 없음) | 79.6% (1528) | 838회 | 85.0% / 90.0% |
| + 무음 스킵 (RMS<0.012) | 70.4% (1352) | 714회 | 85.0% / 90.0% |
| + 연속 확인 2/2/2/3 (**앱 기본**) | **47.6% (914)** | 402회 | 92.5% / 87.5% |
| 앱 기본, 횡단보도 민감도(-0.2) | 48.3% (927) | 407회 | 92.5% / 87.5% |
| 앱 기본, 다중 라벨 모델 | 84.6% (1624) | 966회 | 95.0% / 75.0% |

### #37 전후 비교 (`results_37.json`, `compare.py`)

| 설정 | 클립 오탐율 | 횡단보도(-0.2) | 탐지율 horn / siren |
|---|---|---|---|
| 변경 전: 0.5/0.5/0.5/0.7, 연속 2/2/2/3 | 47.6% (914) | 48.3% | 92.5% / 87.5% |
| **#37 반영: 0.51/0.43/0.49/0.84, 연속 2/2/2/3** | **47.5% (912)** | 47.9% | 92.5% / 87.5% |
| 참고: 위 임계값 + bicycle 연속 2회 (채택 안 함) | 50.4% (968) | 51.4% | 92.5% / 87.5% |

- #37(임계값을 `thresholds.json`에서 읽기)은 오탐율·탐지율에 거의 영향 없음 (914 → 912클립). bicycle 오알림만 108 → 102건.
- bicycle 연속 확인을 3 → 2회로 줄이면 bicycle 오알림이 102 → 209건으로 약 2배 → 3회 유지.
- 오탐의 대부분은 brake(462)·siren(356) 예측이고, 그룹별로는 동물 소리(74.8%)가 가장 높음.

재현:
```
python3 compare.py ESC-50 win.npz results_37.json
```

### 한계
- ESC-50은 5초 클립이라 실제 연속 사용(시간당 오알림)과는 차이가 있음. 실기기 로그로 재확인 필요.
- 탐지율은 클래스당 40클립이라 1클립 = 2.5%p.
